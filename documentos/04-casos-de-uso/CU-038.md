# CASO DE USO CU-038: NAVEGAR Y FILTRAR EL CALENDARIO ACADÉMICO

## Identificación del caso de uso

* **Código:** `CU-038`
* **Nombre:** Navegar y Filtrar el Calendario Académico
* **Módulo:** Módulo 8: Calendario Académico
* **Actor principal:** Aprendiz / Instructor / Administrador
* **Actores secundarios:** Servidor API REST
* **Prioridad:** Alta
* **Estado de implementación:** 🟢 Implementado y Verificado en Rama DEV

## Descripción
Permite a cualquier usuario autenticado navegar entre meses, conmutar entre vista mensual y agenda, y filtrar actividades por categoría institucional.

## Precondiciones
* Usuario autenticado en la plataforma.

## Disparador
El usuario navega entre meses o hace clic en un filtro de categoría.

## Flujo principal
1. El usuario selecciona el mes o pulsa los botones de anterior/siguiente.
2. El usuario selecciona una categoría (CLASE, EVALUACION, ENTREGA, etc.).
3. El frontend envía petición GET /api/calendario con query params de mes, año y categoría.
4. El backend filtra los registros en MySQL y retorna la colección de eventos.
5. El frontend recalcula la cuadrícula mensual y renderiza los badges coloreados según la categoría.

## Flujos alternativos
* 2a. Conmutar a vista Agenda: el sistema renderiza una línea de tiempo vertical con badges numéricos del día.

## Excepciones
* 3a. Error de red o servidor no disponible: se despliega banner de reintento.

## Postcondiciones
* **Éxito:** Cuadrícula y listado sincronizados con los filtros aplicados.
* **Fallo:** Se mantiene el estado previo del calendario.

## Reglas de negocio
* RN-047: Los aprendices solo visualizan eventos públicos institucionales o asignados a su ficha 3413988.

## Datos involucrados
* **Entradas:** `mes, anio, categoria, id_curso`
* **Salidas:** `Array de eventos ordenados cronológicamente`

## Permisos
* `Todos los roles autenticados.`

## Criterios de aceptación
> Tiempo de filtrado reactivo menor a 150 ms en navegador.

## Relaciones UML
* Asociación directa con componente CalendarioModule.

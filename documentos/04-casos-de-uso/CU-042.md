# CASO DE USO CU-042: DETECCIÓN AUTOMATIZADA DE RIESGOS FORMATIVOS (MOTOR DE REGLAS)

## Identificación del caso de uso

* **Código:** `CU-042`
* **Nombre:** Detección Automatizada de Riesgos Formativos (Motor de Reglas)
* **Módulo:** Módulo 10: Sistema de Alertas Tempranas
* **Actor principal:** Motor de Reglas del Sistema (CRON / Background Worker)
* **Actores secundarios:** Coordinador Académico / Instructor
* **Prioridad:** Alta
* **Estado de implementación:** 🟢 Implementado y Verificado en Rama DEV

## Descripción
Ejecuta el motor de reglas en segundo plano o a demanda para identificar inasistencias reiteradas (> 2 ausencias) o evidencias vencidas, generando alertas preventivas automáticas.

## Precondiciones
* Base de datos operativa con registros de asistencia y evidencias.
* Disparador programado o invocación manual desde consola.

## Disparador
Ejecución periódica automática o clic en 'Evaluar Reglas'.

## Flujo principal
1. El servicio consulta los registros de asistencia agrupados por aprendiz con estado AUSENTE.
2. Si un aprendiz acumula 2 o más ausencias sin justificar, verifica si ya existe una alerta activa para evitar duplicados.
3. Si no existe, crea una ALERTA_TEMPRANA con prioridad ALTA o CRÍTICA y origen AUTOMATICA.
4. El servicio consulta las evidencias con fecha límite superada y sin entregas completas.
5. Genera alertas de tipo EVIDENCIA_VENCIDA con prioridad MEDIA.
6. Registra el hito en HISTORIAL_ALERTA con el usuario del sistema.
7. Retorna el conteo total de nuevas alertas generadas.

## Flujos alternativos
* 2a. No se detectan anomalías: el sistema retorna 0 alertas nuevas sin alterar el estado actual.

## Excepciones
* 1a. Falla de conexión a base de datos: error 500 registrado en logs de OpenTelemetry.

## Postcondiciones
* **Éxito:** Alertas tempranas disponibles en la consola preventiva y badges actualizados.
* **Fallo:** No se crean alertas erróneas.

## Reglas de negocio
* RN-052: Prevención de spam: no se genera una nueva alerta idéntica si ya existe una en estado NUEVA o EN_SEGUIMIENTO.
* RN-053: Las alertas automáticas jamás sancionan ni cambian el estado de matrícula sin intervención humana.

## Datos involucrados
* **Entradas:** `Registros de ASISTENCIA y fechas de EVIDENCIA`
* **Salidas:** `Registros insertados en ALERTA_TEMPRANA e HISTORIAL_ALERTA`

## Permisos
* `ADMIN, INSTRUCTOR (invocación manual), Sistema (background).`

## Criterios de aceptación
> Detección exacta de aprendices que superan el umbral de inasistencia.

## Relaciones UML
* include HistorialAlerta; lectura de Asistencia y Evidencias.

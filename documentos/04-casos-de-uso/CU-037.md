# CASO DE USO CU-037: PROGRAMAR EVENTO EN CALENDARIO ACADÉMICO

## Identificación del caso de uso

* **Código:** `CU-037`
* **Nombre:** Programar Evento en Calendario Académico
* **Módulo:** Módulo 8: Calendario Académico
* **Actor principal:** Instructor / Administrador
* **Actores secundarios:** Servicio de Notificaciones y Aprendices de la Ficha
* **Prioridad:** Alta
* **Estado de implementación:** 🟢 Implementado y Verificado en Rama DEV

## Descripción
Permite al Administrador o Instructor crear y agendar eventos institucionales, sesiones presenciales, fechas límites de entrega y evaluaciones, validando rangos horarios y notificando a la ficha correspondiente.

## Precondiciones
* Usuario autenticado con rol INSTRUCTOR o ADMIN.
* Ficha o grupo académico activo en el sistema.

## Disparador
El usuario presiona 'Programar Evento' en el Calendario Académico.

## Flujo principal
1. El actor ingresa al módulo de Calendario Académico.
2. El sistema valida los permisos y despliega el formulario de creación.
3. El actor ingresa título, categoría (CLASE, EVALUACION, ENTREGA, INSTITUCIONAL), fechas, horarios y ambiente.
4. El sistema valida que la fecha y hora final sean posteriores a las de inicio.
5. El sistema registra el evento en la tabla EVENTO_CALENDARIO vinculando el usuario creador.
6. El sistema invoca a NotificationService para alertar a los aprendices asignados.
7. El sistema confirma la programación y actualiza la matriz del calendario en pantalla.

## Flujos alternativos
* 3a. El evento está asociado a una reserva de ambiente: el sistema comprueba la disponibilidad del aula física antes de guardar.

## Excepciones
* 4a. Fecha fin anterior a fecha inicio: el sistema bloquea el guardado con código HTTP 400 y mensaje de error descriptivo.

## Postcondiciones
* **Éxito:** Evento persistido en base de datos y visible en vistas mensual y de agenda.
* **Fallo:** No se guardan cambios y se muestra mensaje de error al usuario.

## Reglas de negocio
* RN-045: Ningún evento puede tener fecha_fin anterior a fecha_inicio.
* RN-046: Los instructores solo pueden programar eventos en fichas donde figuren como asignados.

## Datos involucrados
* **Entradas:** `titulo, descripcion, categoria, fecha_inicio, fecha_fin, hora_inicio, hora_fin, id_ambiente, id_curso`
* **Salidas:** `Objeto evento con ID autoincremental y confirmación JSON`

## Permisos
* `ADMIN, INSTRUCTOR (Token JWT requerido).`

## Criterios de aceptación
> El evento debe aparecer inmediatamente en la cuadrícula del mes y generar alerta en la campana de notificaciones.

## Relaciones UML
* include NotificationService; extend Gestión de Ambientes.

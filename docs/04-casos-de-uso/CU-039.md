# CASO DE USO CU-039: CANCELAR EVENTO DE CALENDARIO CON TRAZABILIDAD

## Identificación del caso de uso

* **Código:** `CU-039`
* **Nombre:** Cancelar Evento de Calendario con Trazabilidad
* **Módulo:** Módulo 8: Calendario Académico
* **Actor principal:** Instructor / Administrador
* **Actores secundarios:** Aprendices Destinatarios
* **Prioridad:** Alta
* **Estado de implementación:** 🟢 Implementado y Verificado en Rama DEV

## Descripción
Permite al organizador cancelar un evento programado, registrando obligatoriamente el motivo de cancelación y notificando la novedad a los participantes.

## Precondiciones
* Evento existente con estado ACTIVO.
* Usuario creador o administrador.

## Disparador
El usuario presiona 'Cancelar Evento' en el modal de detalle.

## Flujo principal
1. El actor abre el modal de detalle del evento.
2. Presiona 'Cancelar Evento'.
3. El sistema solicita el motivo justificado de la cancelación.
4. El actor ingresa el motivo y confirma.
5. El sistema ejecuta PATCH /api/calendario/:id/cancelar actualizando estado a CANCELADO.
6. Se dispara notificación preventiva a los aprendices de la ficha.
7. El evento se conserva visible con etiqueta de cancelación (no se elimina físicamente).

## Flujos alternativos
* No aplican flujos alternativos directos.

## Excepciones
* 4a. Motivo vacío: el sistema cancela la operación y exige justificación.

## Postcondiciones
* **Éxito:** Registro marcado como CANCELADO con motivo preservado en auditoría.
* **Fallo:** El evento permanece ACTIVO.

## Reglas de negocio
* RN-048: Los eventos cancelados no se purgan de la base de datos para preservar trazabilidad.

## Datos involucrados
* **Entradas:** `id_evento, motivo`
* **Salidas:** `Objeto evento con estado CANCELADO`

## Permisos
* `ADMIN, INSTRUCTOR.`

## Criterios de aceptación
> El evento muestra badge rojo de CANCELADO y se notifica a la ficha.

## Relaciones UML
* include NotificationService.
